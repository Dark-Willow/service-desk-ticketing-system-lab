# Lab 05 — Ticket Closure Notes and Documentation

## Objective

The objective of this lab is to practise closing service desk tickets properly after resolution.

This lab focuses on adding user or requester confirmation, recording final closure comments, selecting closure information, and moving tickets from Resolved to Closed.

## Tickets Closed

| Ticket | Scenario | Closure Practised |
|---|---|---|
| Ticket 02 | User unable to log in after password reset | User confirmation and account access closure |
| Ticket 03 | User laptop running slowly | User confirmation and endpoint issue closure |
| Ticket 04 | User cannot connect to Wi-Fi | User confirmation and network issue closure |
| Ticket 05 | New starter needs account setup | Requester confirmation and onboarding closure |

## Ticket 02 — Password Reset Login Issue

The password reset ticket was closed after the user confirmed that they could log in successfully.

The closure note documented that the password reset issue was resolved, access was restored, and no further account access issues were reported.

## Ticket 03 — Slow Laptop Performance

The slow laptop ticket was closed after the user confirmed that the laptop was performing better.

The closure note documented that endpoint troubleshooting and restart guidance had improved the issue and that no further performance issues were reported.

## Ticket 04 — Wi-Fi Connectivity Issue

The Wi-Fi ticket was closed after the user confirmed that they could connect to the wireless network successfully.

The closure note documented that network access had been restored and that no further wireless connectivity issues were reported.

## Ticket 05 — New Starter Account Setup

The new starter ticket was closed after the requester confirmed that account setup had been completed.

The closure note documented that account access, email access, group memberships, and shared resource permissions had been prepared.

## What I Learned

This lab helped me understand the importance of closing tickets properly after resolution.

I learned that a ticket should not only show that an issue was fixed. It should also show that the user or requester confirmed the outcome, that the resolution was documented, and that the ticket was closed with clear final comments.

Good closure notes help create a clear support history. They also make it easier for other technicians to understand what happened, what was done, and why the ticket was closed.
