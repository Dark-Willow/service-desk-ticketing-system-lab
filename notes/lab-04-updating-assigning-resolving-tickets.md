# Lab 04 — Updating, Assigning, and Resolving Tickets

## Objective

The objective of this lab is to practise updating existing service desk tickets after they have been created.

This lab focuses on moving tickets through a basic support workflow from Open to In Progress, adding troubleshooting or request update notes, documenting resolutions, and marking tickets as resolved.

## Tickets Updated

| Ticket | Scenario | Workflow Practised |
|---|---|---|
| Ticket 02 | User unable to log in after password reset | Account access troubleshooting and resolution |
| Ticket 03 | User laptop running slowly | Endpoint performance troubleshooting and resolution |
| Ticket 04 | User cannot connect to Wi-Fi | Network connectivity troubleshooting and resolution |
| Ticket 05 | New starter needs account setup | User onboarding request processing and resolution |

## Ticket 02 — Password Reset Login Issue

The password reset ticket was updated from Open to In Progress while the account access issue was investigated.

A troubleshooting update was added to document that the user account was checked, the username was verified, account lockout was considered, and the user was asked to test login again using the temporary password.

The ticket was then resolved after the password reset process was completed again and the user was confirmed as able to log in successfully.

## Ticket 03 — Slow Laptop Performance

The slow laptop ticket was updated from Open to In Progress while the endpoint performance issue was investigated.

A troubleshooting update was added to document checks such as Task Manager, CPU usage, memory usage, disk usage, available storage, startup applications, Windows updates, and Event Viewer.

The ticket was resolved after basic endpoint troubleshooting and restart guidance, with the user confirming that laptop performance improved.

## Ticket 04 — Wi-Fi Connectivity Issue

The Wi-Fi ticket was updated from Open to In Progress while the wireless connectivity issue was investigated.

A troubleshooting update was added to document checks such as Wi-Fi status, correct wireless network selection, forgetting and reconnecting to Wi-Fi, restarting the wireless adapter, checking IP configuration, and testing connectivity using ping.

The ticket was resolved after the device was reconnected to the correct wireless network and successful connectivity was confirmed.

## Ticket 05 — New Starter Account Setup

The new starter ticket was updated from Open to In Progress while the onboarding request was processed.

A request update was added to document checks such as the new starter’s name, start date, department, manager, required systems, email access, shared resource access, and group memberships.

The request was resolved after the account setup was completed, group memberships were assigned, email access was checked, and shared resource permissions were confirmed.

## What I Learned

This lab helped me understand how service desk tickets are managed after they are created.

I practised changing ticket status, adding clear troubleshooting updates, recording next actions, documenting resolutions, and marking tickets as resolved.

I learned that good ticket updates should explain what was checked, what action was taken, what the next step is, and how the issue was resolved.

This is important because service desk tickets are not only used to log user issues. They are also used to track ownership, show progress, record troubleshooting, support handovers, and provide a clear history of the work completed.
