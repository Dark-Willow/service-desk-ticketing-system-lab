# Lab 06 — Final Service Desk Workflow Summary

## Objective

The objective of this lab is to summarise the full service desk workflow practised in this project.

This lab brings together the full ticket lifecycle from creating a ticket, categorising it, updating it, resolving it, recording user confirmation, and closing the ticket.

## Workflow Practised

The project followed this service desk workflow:

1. User or requester reports an issue
2. Ticket is created
3. Ticket is categorised
4. Priority, urgency, and impact are set
5. Technician and support group are assigned
6. Ticket is moved to In Progress
7. Troubleshooting or request update notes are added
8. Resolution is documented
9. Ticket is marked as Resolved
10. User or requester confirmation is recorded
11. Ticket is Closed

## Scenarios Covered

| Scenario | Area Practised |
|---|---|
| User cannot access internal shared drive | Access issue documentation |
| User unable to log in after password reset | Account access troubleshooting |
| User laptop running slowly | Endpoint troubleshooting |
| User cannot connect to Wi-Fi | Network troubleshooting |
| New starter needs account setup | User onboarding request |

## What I Learned

This project helped me understand how service desk teams manage user issues from the first report through to closure.

I practised creating tickets, setting priority and urgency, assigning groups and technicians, adding troubleshooting notes, writing resolution notes, recording user confirmation, and closing tickets.

I also learned that good ticket documentation should clearly show what the user reported, what was checked, what action was taken, what the final resolution was, and why the ticket was closed.
